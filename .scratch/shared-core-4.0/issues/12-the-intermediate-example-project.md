## Answer

Built in 354722e, fixed up after review in 73c5ce6.

- **The layout.** `example_projects/intermediate/`, on `ops.job_events`, `ops.job_owners` and
  `ops.region_costs`: `settings.py` (Level 0: per table its name, Date partition, key and the
  columns to add up); `table_references/` (three generated by write_table_reference with their
  TODO lines filled in, region_costs' Date partition too: `date_partition="dt"`,
  `date_format="%Y%m%d"`, with the reason; three Saved tables by hand: `mart.job_day_costs`,
  `mart.job_day_facts`, `mart.team_days`); `building_blocks/` (`events_per_job_day(first_day,
  last_day)`, `owner_on_day(job_id_column, day_column, first_day, last_day)`, a LEFT_JOIN as a
  Building block, `costs_per_job_day`, which bounds the compact days with `datetime.date`, and
  `jobs_without_events`, an anti-join); `statements/` (three examples and `quality_checks.py`);
  `run_pipeline.py`; generated `lineage/`; a README naming every file.
- **Where it differs from the layout asked for, and why:**
  - **Example 1 saves costs, not facts.** Two tables whose Date partitions are written
    differently can't be joined on the day in one Statement: `equals(region_costs.dt,
    job_events.dt)` builds without a word and matches nothing. A write fills
    `PARTITION(dt = '...')` written the Saved table's way, so example 1
    (`example_1_job_day_costs.py`) saves each job's cost per day in `mart.job_day_costs` as
    2026-09-24, and from then on the costs join on the day. Its incremental-load story is the
    late bill (invoice_sync's 2026-09-24 cost is NULL). Example 2 (`example_2_owner_as_of.py`)
    saves each job's events, runs and minutes with its team as of that day in
    `mart.job_day_facts`, plus `newest_owners(day)` (row_number) and
    `newest_owners_by_newest_day(day)` (max_of per job, joined back), which sqlglot's executor
    runs. Example 3 reads both Saved tables.
  - **No weekly Saved table.** A write fills one day, and the Toolbox refuses a write that
    covers 7 days, so example 3 saves `mart.team_days` and `week_totals(first_day, last_day)`
    adds each team's days into weeks with `week_start`, which is right since every number adds
    up.
  - **No quality_results Saved table.** `run_pipeline.check_all(send, day)` gathers the checks
    in pandas, as how-to 25 says.
  - **One write step, `write_days(first_day, last_day)`,** in place of the starter's
    `write_day` and `backfill`: every run writes the last 3 days, and a backfill is an earlier
    first day (`backfill_from` in `run_pipeline.py`). The README says so.
  - **The lineage review's "before" file** is written by the generator from a temporary copy of
    the project with the edit undone (`REVIEWED_EDIT`), since the old code must not stay in the
    project; the README shows the edit as a diff, held to `REVIEWED_EDIT` by a test.
  - **"measures" became `"add_up"`:** not a glossary word. job_events has none, since its
    minutes are minutes since each run started, which mean nothing added up.
- **The quality checks** (`every_check(first_day, last_day)`): per table from settings.py,
  `repeated_keys` (over the days read, where check_key looks at the newest day), `null_counts`
  (every column from `all_columns`), `rows_per_day`; by hand, `costs_billed_and_saved` (two
  one-row Derived tables side by side with CROSS_JOIN, since the days can't be joined) and
  `jobs_not_run`.
- **run_pipeline.py:** `steps(day, backfill_from=None)`, `in_order`, `send_all(send, day,
  backfill_from=None)`, `dry_run(day, ...)` (12 steps headed such as
  `-- 4 of 12: write_job_day_costs[0]`), `check_all`, `write_lineage_files(day)` (each example,
  all three, and the review's "after" file) and `write_lineage_review(day, to)`.
- **The generator.** `intermediate` in `FILLED_IN`, which can now fill a Date partition TODO
  (`HOW_WITH_THE_DATE_PARTITION`); `REVIEWED_EDIT` and `write_review_before_the_edit`, which
  refuses with `EditMissing` if the edited line isn't there. Byte-stable in both Editions.
- **The tests.** `tests/test_example_projects.py`, in both Editions: the regeneration byte test
  for each project; no TODO left; the Table references match the Example database's, with
  date_format; settings.py's keys and Date partitions match the Table references'; the review
  edit's refusal, README diff and before/after files (differing only by the edit, which reaches
  mart.team_days' minutes); every step builds; each write_days writes each day once, oldest
  first; previews of examples 1 and 2, the newest owner both ways, example 3's grouping, its
  preview and each day of its write_days (with the Saved tables stood in for by what examples 1
  and 2 preview), week_totals, and every quality check match pandas; every SELECT the Example
  database can run runs. sqlglot Composer's run skips the row_number tests (3) and week_totals
  (1), saying why; Spark Composer's runs them. The run order, the 3-day window and a 14-day
  backfill, the dry run, send_all and check_all; the README names every file and step.
  `tests/repo/test_levels.py` puts settings.py at Level 0 (`LEVEL_0_BESIDE`), and CONTEXT.md's
  **Level** says so.
