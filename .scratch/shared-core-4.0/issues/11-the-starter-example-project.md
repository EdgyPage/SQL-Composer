## Answer

Built in bf62eea, fixed up in the lineage fix and the commit that resolves this ticket.

- **The layout.** `example_projects/starter/`, on `ops.jobs`, `ops.job_runs` and
  `ops.run_alerts`: `table_references/` (Level 0: three generated by write_table_reference with
  their TODO lines filled in and marked `# filled in by hand`, and the three Saved tables'
  written by hand), `building_blocks/runs_per_job_day.py` (Level 1, a Derived table examples 1
  and 3 read), `statements/` (Level 2: example 1 saves each job's runs per day in
  `mart.daily_job_runs`, example 2 each job's alerts in `mart.alerts_per_job`, example 3 reads
  both and `ops.jobs` to save each team's day in `mart.team_day`), `run_pipeline.py` above the
  Levels, `lineage/` (generated) and a README naming every file.
- **The steps.** Each example has `create()`, `preview(day)` (a SELECT, the only step with a
  day filled in: the Example database's last day), `write_day(day)` and
  `backfill(first_day, last_day)`, which builds write_day's Statement once over all the days
  and lets by_day cut it into one write per day, the day kept in GROUP_BY. Example 3 also has
  `team_runs_from_job_runs(day)`, which runs its team grouping on the Example database.
  `run_pipeline.py` has `steps(day)`, `send_all(send, day)`, `dry_run(day)` (show_hive, each
  step headed by its variable, such as `-- 4 of 6: write_daily_job_runs`) and
  `write_lineage_files(day)`.
- **The generator.** `python tools/example_project.py [--project starter] [--edition spark]
  [--into DIR]` writes the generated files in a second Python whose folder is the project's.
  It refuses an `--into` folder that holds anything. The lineage's time and commit are pinned
  (`pinned`); its version is `edition.PRODUCT` and `TOOLBOX_VERSION`, so the lineage says which
  Toolbox wrote it, and ticket 15 reruns the generator after raising the version (the map's
  Notes say so). It runs no SELECT, so Spark Composer's needs no Java.
- **The tests.** `tests/test_example_projects.py`: the project regenerated in each Edition and
  compared byte for byte; the `--into` refusal; no TODO left; the generated Table references
  match the Example database's; every step builds (one `statement_functions(module)` helper
  calls each function with its days); preview is the SELECT write_day sends; backfill writes
  the days write_day does, and on the Example database each day of examples 1's and 2's
  backfill saves what that day's preview shows; example 2 reads job_runs from the day before
  in both writes; example 3's Hive reads both Saved tables and `ops.jobs`, and its preview,
  with the Saved tables stood in for by the rows examples 1 and 2 preview, gives the team
  totals pandas works out; only previews have a day filled in; the pipeline's order, dry run
  and send_all; the README names every file and step. `tests/repo/test_levels.py` holds each
  Example project's Levels and docstrings.
