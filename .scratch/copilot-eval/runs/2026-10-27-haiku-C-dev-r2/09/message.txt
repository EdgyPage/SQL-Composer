## Reading a refusal

Every refusal has four parts: What happened, Why it matters, Usual fix, Opt-out. Follow the
Usual fix. The Opt-out is a keyword that tells the Toolbox the user has checked what it
refuses; use it only when the user says so, and never to make an error go away.

## Common refusals, by what happened, and the fix

- "A column was used with Python's ==." (or <, >, and, or): write the Condition with a
  function: `equals(t.status, "FAILED")`, `more_than(...)`, `all_of(...)`, `any_of(...)`.
- "FROM(job_runs) reads ops.job_runs, but filters none of its partition columns: dt.": add a
  bound, `WHERE(equals(job_runs.dt, "2026-09-24"))`, or between, is_in, last_n_days. For a
  LEFT_JOIN, SEMI_JOIN or ANTI_JOIN, the bound goes inside ON=. Matching `t.dt` to another
  table's dt is no bound. Every day, asked for: `reads_all_partitions=True`.
- "ORDER_BY has no LIMIT.": add `LIMIT(n)` for a top n, or sort the DataFrame in pandas.
- "WHERE has job_owners.owner = 'ana', a condition on job_owners, which LEFT_JOIN brought
  in.": move that Condition into `LEFT_JOIN(job_owners, ON=all_of(..., ...))`, beside the
  join's own Condition.
- "SELECT has a calculation with no name: COUNT(*).": name it, `AS(count_rows(), "runs")`.
- "SELECT has job_runs.status, which GROUP_BY leaves out.": add it to GROUP_BY, or count or
  add it up.
- "equals(job_runs.status, None) compares with None.": `is_null(t.status)` or
  `is_not_null(...)`.
- "statement(...) has its clauses out of SQL order: FROM, SELECT.": put them in order:
  SELECT, FROM, joins, WHERE, GROUP_BY, HAVING, ORDER_BY, LIMIT; a write's clause first.
- "JOIN(job_runs) has no ON=.": give ON=, or `CROSS_JOIN(t)` for every row with every row.
- "RIGHT_JOIN(jobs, ...): the Toolbox doesn't write a RIGHT JOIN.": swap the two tables and
  use LEFT_JOIN.
- "... both sides are tables called jobs.": give one a second name, `j2 = AS(jobs, "j2")`.
- "sum_of(average_of(...)) adds up ..., which is an average.": add up the parts instead,
  such as a sum and a count, and divide; `adds_up=True` only when it truly adds up.
- RepeatedRowsWarning, "LEFT_JOIN(job_runs) matches on job_id, but a job_runs row is told
  apart only by its Key (run_id).": join on the whole Key, or join a Derived table grouped
  to one row per value; `many_matches=True` only when the repeats are wanted.
- A write refused for its columns: SELECT exactly the Saved table's columns, by name, the
  partition column last.
- A write refused for its Key: give one row per Key, with GROUP_BY over the Key,
  SELECT_DISTINCT, or a row_number kept at 1.
- "run_query was given send=, which Toolbox 7.0 replaced.": `run_query(s, query)` for a read,
  `run_execute(s, execute)` for a write.
