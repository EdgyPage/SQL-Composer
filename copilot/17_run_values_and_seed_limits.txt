# Copilot file 17: Run values, answers for every table, and seed limits (sqlglot Composer 8.9)

**Find the request in Patterns, copy the cells it names, filled in with the user's names,
then tick the Self-check. Answer only what the user gives; add no cell they didn't ask for.**

Objective: write the user's function that works out a Run value each time a table is
written, and the decisions cell answers using it: a Script tag's, a Hivevar, one for every
table, a seed's limits. Load this file when the user wants a tag's day worked out at each
run, one answer for every table, or a seed of some Partitions. It also gives the convert
Workflow's other cells when asked.

## Terms

- **Script tag**: a `<PARM="NAME"/>` in Hive someone else wrote, which the program that ran
  it filled in; a Conversion leaves each as a Decision of its table, under "tags".
- **Decision**: one thing about one table only the user decides, answered in a Workflow
  notebook's **decisions cell**, DECISIONS; the answers' step (convert's step 3) writes each
  into the table's **Table reference**, the file of its columns, partitions, Key and TAGS.
- **Run value**: what a function gives each time a Statement is built, written into the Hive
  as plain text: a `datetime.date` as '2026-09-24', a number as it is.
- **Partition**: the rows of a table that share one value of each partition column.
- **Seed**: step 5's one copy of the original's rows into a table that reads itself.

## Rules

- **R1** A tag for a day that changes each run is answered with a Run value; one fixed day
  the user gives, with text. A tag is where the old scheduler put its value: that alone asks
  for no Hivevar.
- **R2** Only if the user asks for a Hivevar: `hivevar("PERIOD_END", default=period_end)`
  under "tags", `hivevar` imported.
- **R3** Answer with the function's name, no brackets: `{"tags": {"PERIOD_END":
  period_end}}`. It lives in a Project file, imported at the top of the cell; one made in a
  cell, a lambda or a nested one is left unwritten.
- **R4** The newest Partition of a table: `project.new_run_value("period_end",
  latest_partition="ops.job_runs.dt", query=query)` writes `latest_partition(job_runs.dt,
  query)` in building_blocks/run_values.py and registers it, adding the table's Table
  reference if it has none. Today: `today()` in UTC,
  `today(utc_offset_hours=-6)` six hours behind.
- **R5** No Partition names it: the function runs a Statement of its own with run_query,
  each partitioned read bounded, and takes no argument (W1).
- **R6** "all_tables" holds only "tags", "seed" and `"key": "proposed"`; a table's own answer
  overwrites it, kind by kind. Any other Key, a type and a location go under each table.
- **R7** Answer what the user gives, no more: `"key": None` if no columns name one row;
  `"key": "proposed"` only if they accept the proposed Keys.
- **R8** A folder for every table: each table's own location under it,
  `<folder>/<database>.db/<table>`: "/data/team/mart_dev.db/daily_fails_mart".
- **R9** "seed", by partition column: a value, **that value or later**; `{"from": ...,
  "to": ...}`, either end left out; a list, those values alone; numbers as numbers; a Run
  value's function. A column left out is copied whole; no "seed", every Partition.
- **R10** A Run value in a Statement the user writes: `run_value(function, *arguments)`. In
  Hive written by hand (file 10): `hive_date(day)`, '2026-09-24' in quotes.
- **R11** Give only the cells asked, never a step the user has run, such as convert. Asked
  for convert's other cells, give each in order: the names cell, `NAME`, `FILES =
  ["daily.hql"]` by name, `HIVE = None`, `DATABASE = "default"`, `RENAME = {}`, `STAGING =
  {}`, `PARTITIONS = []`; step 1, `project.convert(NAME, HIVE, files=FILES, query=query,
  database=DATABASE, rename=RENAME, staging=STAGING)`; the decisions cell and step 3; then
  steps 4 to 7 (W3). The name the user says convert gives is its own: `RENAME = {}`.

## Worked patterns

### W1: building_blocks/run_values.py, a day no Partition names

```python
import datetime

from sqlglot_composer import (AS, FROM, SELECT, WHERE, at_least, equals, latest_partition,
                              max_of, run_query, statement)
from references.ops__job_runs import job_runs
from warehouse import query


def last_good_day() -> datetime.date:
    """The latest day a run succeeded, of the last 30 days ops.job_runs holds."""
    first = str(latest_partition(job_runs.dt, query) - datetime.timedelta(days=30))
    rows = run_query(statement(SELECT(AS(max_of(job_runs.dt), "day")), FROM(job_runs),
                               WHERE(at_least(job_runs.dt, first),
                                     equals(job_runs.status, "SUCCESS"))), query)
    return datetime.date.fromisoformat(rows["day"][0])
```

### W2: the decisions cell and step 3: PERIOD_END by period_end, Keys accepted, a seed

```python
project.new_run_value("period_end", latest_partition="ops.job_runs.dt", query=query)

```

### W3: convert's steps 4 to 7, a cell each: create, seed, write, compare

```python
for table in project.batch_tables(NAME):
    run_execute(project.load(table).create(), execute)

to_seed = project.batch_tables(NAME, seeded=True)
if not to_seed:
    print("Seeded nothing: no table of the batch reads itself.")
else:
    run_execute(hive_settings("dynamic_partitions"), execute)
    for table in to_seed:
        run_execute(project.load(table).seed(), execute)

project.run_tables(tables=project.batch_tables(NAME), execute=execute)

project.compare_batch(NAME, query=query, partitions=PARTITIONS)
```

## Steps

1. **Find.** Match each part of the request to a Patterns row. Then step 2.
2. **Function.** Write the function only if one is asked for and the user hasn't one (W1, or
   `project.new_run_value` at the top of the decisions cell). Then step 3.
3. **Copy.** Write the cells asked, in order, with the user's names. Then step 4.
4. **Name the rest** in words: each later step through step 7's compare. Then step 5.
5. **Check.** Tick each Self-check line; fix any that fails, then reply as Output says.

## Output

1. building_blocks/run_values.py in a ```python block, if step 2 wrote it.
2. The cells asked, in order, in ```python blocks.
3. In words: each later step, and `project.register("run_values")` for a file by hand.
