# Copilot file 15: an Excel workbook into Hive, step by step (sqlglot Composer 8.8)

**Follow the steps below in order, as written: give each piece its role from Patterns, write
each final's Hive by files 11, 12 and 20, then tick the Self-check. Reply as Output says.**

Objective: turn the calculations of an Excel workbook the user attaches, or the text
`workbook_text.py` writes of it, into one Hive query per final, for the convert Workflow.
Load this file when the user attaches a workbook and asks for its calculations as Hive, with
file 11 (each formula's Hive), file 12 (Power Query and totals) and, for a PivotTable, file 20.

## Patterns: when the workbook has X, its role is Y

| ID | The workbook has | Role |
|---|---|---|
| P1 | a Table of typed columns only, no query loading it | source, never a final |
| P2 | a Table with a formula column that another Table or a query reads | step, a CTE |
| P3 | a Table with a formula column nothing else reads | final |
| P4 | a Table whose only typed columns are its -IFS match columns | summary final (R1) |
| P5 | a query named in another query's M | step, a CTE in each final reading it |
| P6 | a query loading a Table another Table's formula reads | that Table a step |
| P7 | a query loading a Table nothing reads | that Table a final, its rows the query's |
| P8 | a query that loads nothing and nothing reads | left out, and named |
| P9 | a Table with a Total Row | also a final, `<Table> (Total Row)` (R2) |
| P10 | Parameters, Keys | settings: never a source, step or final |
| P11 | pieces reading each other in a loop | each final in it refused, named |
| P12 | a PivotTable a Table's GETPIVOTDATA reads | step, a CTE (file 20) |
| P13 | any other PivotTable | final, and each total level shown (file 20) |

## Terms

- **Table**: an Excel Table, shown as `Excel Table "name"`, its headers, rows and any Total
  Row.
- **Typed column**: a column whose cells hold values; a **formula column** holds formulas.
- **Query**: a Power Query, listed after the sheets as `Power Query "name"`, its M below. A
  query and the Table it loads are two pieces, even with one name. A query's name in
  another query's M, as `Table.Sort(owner_load, ...)`, is that query.
- **Sample**: a Table's typed rows are a sample of a database table of the Table's name,
  which holds more rows: read the table, never the sample.
- **Source**: a database table a final reads, `<database>.<table>`. **Step**: a Table or
  query a final reads, as a CTE. **Final**: a Table or PivotTable given a query of its own.
- **Mark**: a formula converted where Excel and Hive can differ, named in the map (file 11).
- **Parameters**, **Keys**: the workbook's two settings Tables, read by step 5.

## Rules

- **R1** A summary is a Table whose only typed columns are the ones its SUMIFS, COUNTIFS,
  AVERAGEIFS, MAXIFS, MINIFS or GETPIVOTDATA match on. Its final is a GROUP BY of the Table it reads, its typed rows kept,
  written into the Hive and named in the map, since a later day or team won't be in the
  table; it keeps the summary Table's own name.
- **R2** A Total Row's final has a column for each Total Row cell holding a total, no other.
- **R3** A Table with a formula column and no query loading it is a step if another Table's
  formula or a query reads it, else a final; its own formula columns reading its own row
  don't count. A query loading a Table: the Table is a step if another Table's formula reads
  it, else a final, its rows the query's.

## Rules: Hive that stays small

- **H1** Read each step once in a final: Hive works a CTE out at each read (4.1 keeps one
  with totals read over 3 times). Forms grouped alike share one join (file 11's F9).
- **H2** A CTE selects only the columns read after it, never `*`: Hive drops the rest, but a
  short CTE is quicker to check.
- **H3** Each WHERE goes in the SELECT that reads its source, before any join.
- **H4** For reading: rename or add columns in the SELECT that reads a step, never in a CTE
  that only copies it.
- **H5** No ORDER BY without LIMIT in a CTE or subquery: Hive drops it. Fix a join that
  repeats rows in its ON, never with a DISTINCT after it.

## Steps

1. **Read.** Goal: see all of the workbook. Action: list each `Excel Table` with its typed
   and formula columns and Total Row, each defined name, and each `Power Query` after the
   sheets, with what each reads: its line under `Order, each piece after every piece it
   reads:`, or else each Table and query its M or formulas name. Done when every piece is
   listed with what it reads. Then step 2.
2. **Decide each role.** Action: give each piece its role from Patterns, one row per piece,
   a query apart from its Table. Done when each piece has a role. Then step 3.
3. **Write the map.** Action: write the Output's map from steps 1 and 2. Done when it names
   each piece. Then step 4.
4. **Write each final's reads.** Action: start each final's query: each source as
   `<database>.<table>`, each step it reads as a CTE (`WITH name AS (...)`), each CTE after
   every CTE it reads. **A Table's typed columns are always read from
   `<database>.<table>`, never typed in**; only a summary's groups are written into the
   Hive. Then step 5.
5. **Write each final's columns.** Action: the columns in the Table's order, each formula by
   file 11, each query step and total by file 12, each pivot by file 20, each named with AS; a
   Parameters value read in as its value; a value typed over a formula matched on its Keys
   row's columns. Done when each final's block is whole. Then step 6.
6. **Name what changed.** Action: list each mark, each refusal (NULL in its place, with
   why), each thing left alone, and each `<...>` to fill in. Then step 7.
7. **Check.** Action: tick each Self-check line; fix any that fails, then reply.

## Output

Reply with these parts, in this order, and nothing else:

1. **Map**: Sources, Steps and Finals, each with its columns; then each value written in,
   each value typed over a formula, each mark, each refusal, what was left alone, and
   each `<...>` to fill in.
2. **Hive**: a heading and one ```sql block per final, Total Rows included, nothing between.
3. **Next**: "Take out what you don't want, fill in each `<...>`, save each query as a .hql
   file named for its final, and run the convert Workflow on them as one batch (file 13)."

## Worked patterns

### W1: a lookup into a typed Table

Table jobs (job_id, job_name), typed. Table job_runs (run_id, job_id, duration_mins) adds
job_name `=XLOOKUP([@job_id],jobs[job_id],jobs[job_name])`. Map: Sources jobs, job_runs. Finals
job_runs.

```sql
SELECT r.run_id, r.job_id, r.duration_mins, j.job_name
FROM <database>.job_runs r
LEFT JOIN <database>.jobs j ON r.job_id = j.job_id
```

### W2: a query read by another query, each loading a Table

Query ok_runs keeps job_runs' SUCCESS rows and loads Table ok_runs; query ok_by_job reads
query ok_runs and loads Table ok_by_job. Map: Sources job_runs. Steps query ok_runs. Finals
Table ok_runs and Table ok_by_job: no formula reads either Table.

```sql
SELECT run_id, job_id, duration_mins FROM <database>.job_runs WHERE status = 'SUCCESS'
```

```sql
WITH ok_runs AS (
  SELECT job_id FROM <database>.job_runs WHERE status = 'SUCCESS'
)
SELECT job_id, COUNT(*) AS runs FROM ok_runs GROUP BY job_id
```

### W3: a summary with a Total Row

Table by_job (job_id typed; runs `=COUNTIFS(job_runs[job_id],[@job_id])`) with a Total Row
summing runs. Map: Sources job_runs. Finals by_job, a summary, and by_job (Total Row),
file 12's W2. Values written in: by_job's groups, job_ids 1 and 2:

```sql
SELECT j.job_id, COALESCE(c.runs, 0) AS runs
FROM (SELECT 1 AS job_id UNION ALL SELECT 2) j
LEFT JOIN (SELECT job_id, COUNT(*) AS runs FROM <database>.job_runs GROUP BY job_id) c
  ON j.job_id = c.job_id
```
