# Copilot file 06: saving a table (sqlglot Composer 8.5)

**Follow the steps below in order, as written, adding none; reply as the Output section says.**

Objective: write a Saved table from a Statement, in its Table notebook.
Load this file when the user wants to save rows into a table of their own, write a day of
it, add to it, or write the logic cell of a Table notebook.

## Terms

- **Saved table**: a table of the user's that a Statement (`statement(...)`) writes; its
  Table reference (file 02) lists its columns, Partitions, Key and location.
- **Partition**: the rows sharing one value of each partition column. **Key**: the columns
  whose values name one row.
- **Table notebook**: tables/<db>__<table>/<db>__<table>.ipynb; its **logic cell**, first
  line `# logic`, holds only imports, constants and functions, and runs no Hive.
- **Session setting**: a Hive SET a write may need first, from `hive_settings(...)`.

## Always

1. Import each name you use, by name: `from sqlglot_composer import FROM, SELECT, statement`,
   never `import *`. Write only Toolbox names this file or the user's code shows. Hive's own
   words are Toolbox names only where this file writes them as functions, as SELECT and
   FROM: there is no COUNT, SUM, AND, CASE or ALIAS.
2. Build a Statement with `statement(...)`, its Clause functions in SQL order: a write's
   INSERT_OVERWRITE or INSERT_INTO first, then SELECT or SELECT_DISTINCT, FROM, the joins,
   WHERE, GROUP_BY, HAVING, ORDER_BY, LIMIT.
3. Name every calculation with AS: `AS(count_rows(), "runs")`; a plain column needs none.
   Arithmetic, `+ - * /`, works on Columns; write comparisons by rule 4.
4. Write each Condition with a function, in place of Python's ==, <, >, and, or, not on a
   Column: equals, not_equals, more_than, less_than, at_least, at_most, between, is_in,
   is_not_in, is_null, is_not_null, all_of, any_of. WHERE(a, b) keeps rows where both hold.
5. **Bound every read of a partitioned table** with a Condition giving a value for one of its
   partition columns, such as `equals(t.dt, "2026-09-24")`, `between(...)`, `is_in(...)` or
   `last_n_days(t.dt, 7)`: in WHERE for FROM, JOIN and CROSS_JOIN; inside ON= for LEFT_JOIN,
   SEMI_JOIN and ANTI_JOIN; for FULL_JOIN, in a Derived table it reads. Matching it to another
   table's column bounds nothing. A table with no partitions needs no bound.
6. Give every ORDER_BY a LIMIT.
7. Run a read with `run_query(s, query)` and a write with `run_execute(s, execute)`, after
   `from warehouse import query, execute`. Never call query or execute yourself.
8. Add an opt-out, such as `reads_all_partitions=True`, only when the user asks for what it
   allows, and say why in a comment.
9. Reach a column as `table.column`, from the user's Table reference:
   `from references.ops__job_runs import job_runs`, then `job_runs.dt`.
10. The user loads one Copilot file per chat, or for an Excel workbook files 15, 11 and

## Steps

1. **Write the logic cell**, in the Example's shape, naming each calculation after its
   column: `AS(count_rows(), "events")`. Done when write()'s SELECT gives exactly the
   table's columns, by name, in order, the partition column last. Then step 2.
2. **Pick the write** and the Key's proof by the Decision rules. Done when write() starts
   with its write clause. Then step 3.
3. **Write the next cell**, by the Decision rules. Then step 4.
4. **Check** by the Self-check; fix what it finds wrong, then reply.

## Decision rules

- If each Partition the rows hold, such as a day, is replaced: INSERT_OVERWRITE.
- If the rows are added to what is there: INSERT_INTO; a rerun adds them twice.
- If one named Partition is written: `INSERT_OVERWRITE(t, partition={"dt": day})`, its
  column left out of SELECT.
- If the table has a Key: one row per Key, by GROUP_BY over it, SELECT_DISTINCT or a
  row_number kept at 1 (file 05), or the write is refused. `unproven_key=True` only if the
  user says why the rows are one per Key.
- If the user sends one table by hand: `run_execute(create(), execute)` once, then
  `run_execute(hive_settings("dynamic_partitions"), execute)`, which a write filling its
  rows' Partitions needs, then `run_execute(write(), execute)`.
- Otherwise: the next cell runs `show_hive([create(), write()])`, the Hive and any Session
  setting, and `run_query(preview(), query)`, the rows; run_tables sends.

## Output

One Python code block the user can paste into a notebook cell, then a few plain sentences.

## Example

The logic cell of mart.job_day_events, each job's events of a day. Its Table reference lists
job_id bigint, events bigint and dt string, partitioned by dt, Key job_id and dt, and a
location (file 02).

```python
# logic
from sqlglot_composer import (AS, FROM, GROUP_BY, INSERT_OVERWRITE, SELECT, WHERE, Clause,
                              Statement, count_rows, create_table, equals, statement)
from references.mart__job_day_events import job_day_events
from references.ops__job_events import job_events

READS = equals(job_events.dt, "2026-09-24")
PARTITIONED_BY = ["dt"]


def create() -> Statement:
    return create_table(job_day_events, may_exist=True)


def rows() -> list[Clause]:
    return [
        SELECT(job_events.job_id, AS(count_rows(), "events"), job_events.dt),
        FROM(job_events),
        WHERE(READS),
        GROUP_BY(job_events.job_id, job_events.dt),
    ]


def preview() -> Statement:
    return statement(*rows())


def write() -> Statement:
    return statement(INSERT_OVERWRITE(job_day_events), *rows())
```

## Self-check

- write() starts with its write clause; its SELECT gives the table's columns, in order.
- A Key is proved; a day replaced is INSERT_OVERWRITE; each partitioned read is bounded.
- The logic cell calls no run_query or run_execute.
