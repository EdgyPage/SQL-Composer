# Copilot file 02: Table references (sqlglot Composer 8.9)

**Find the request in Patterns, copy the worked pattern it names, change only the tables,
columns and values, then tick the Self-check. Add nothing the user didn't ask for.**

Objective: describe a table to the Toolbox with a Table reference, and check what it says.
Load this file when the user adds a table to read, writes the Table reference of a new Saved
table, or asks about a table's columns, partitions or Key.

## Terms

- **Toolbox**: sqlglot Composer 8.9, which writes Hive from Python.
- **Table reference**: the file references/<database>__<table>.py, such as
  references/ops__job_runs.py, defining one table's Table.
- **Key**: the columns that tell one row from another.
- **Saved table**: a table the user's own notebook writes.
- **Decision**: what only the user answers, in a Workflow's decisions cell.
- **Verdict**: what a check gives back: `print(v)` says what it found; `if v:` is true when
  it holds.

## Rules

- **R1** The variable and the file are named after the table: `job_day_runs` in
  references/mart__job_day_runs.py; the Table's name is "database.table".
- **R2** `columns=`: each column with its Hive type: string, int, bigint, double, boolean,
  date, timestamp, decimal(10,2), array<string>, map<string,int>, struct<name:string>.
  Never a Python type such as `int` or `str`.
- **R3** `partitioned_by=["dt"]` names the partition columns, each listed in `columns` too,
  last. A table with no partitions leaves it out.
- **R4** If the user names a Key, write it as `key=`. If not, leave `key=` out, or ask.
- **R5** `does_not_add_up=["share"]`: columns the Toolbox refuses to add up, such as a share
  or an average. Emptied, `does_not_add_up=[]` refuses none.
- **R6** A Saved table gets a `location=`; a table only read gets none.
- **R7** `descriptions={"status": "FAILED, SUCCESS or NULL while running"}` says what a
  column means, for Lineage and the Reference sheet.
- **R8** A Condition used often may sit beside its Table: `finished = is_in(...)`.
- **R9** `check_key(t, query=query, where=...)` counts whether the Key tells each row apart
  on the Partitions `where=` names; `check_table_reference(t, query=query)` lists what
  differs from the table now; `first_look(t)` is a Statement of 20 rows.
- **R10** A table that exists: the references Workflow runs
  `project.add_references(["ops.job_runs"], query=query)`, writing its Table reference from
  the warehouse. Its proposed Key is a Decision: `{"ops.job_runs": {"key": "proposed"}}`
  accepts it, `["run_id"]` gives one. A new Saved table's comes from its logic,
  `project.reference_from_logic(TABLES)` (file 14).
- **R11** A line ending `# TODO` waits on nothing: fill it in when the user can. A line
  marked `# proposed` is a guess the user accepts or changes; if they doubt a Key,
  `check_key` on one Partition first (W2).

## Always: rules A1 to A11

- **A1** Import each name you use, by name: `from sqlglot_composer import FROM, SELECT,
  statement`, never `import *`. Write only Toolbox names this file or the user's code shows:
  there is no COUNT, SUM, AND, CASE or ALIAS function.
- **A2** One `statement(...)`, its Clause functions in SQL order: a write's INSERT_OVERWRITE
  or INSERT_INTO first, then SELECT or SELECT_DISTINCT, FROM, the joins, WHERE, GROUP_BY,
  HAVING, ORDER_BY, LIMIT.
- **A3** Name every calculation with AS: `AS(count_rows(), "runs")`; a plain column needs
  none. `+ - * /` work on Columns; comparisons are A4's.
- **A4** Write each Condition with a function, never Python's ==, <, >, and, or, not on a
  Column: equals, not_equals, more_than, less_than, at_least, at_most, between, is_in,
  is_not_in, is_null, is_not_null, all_of, any_of. WHERE(a, b) keeps rows where both hold.
- **A5** **Bound every read of a partitioned table** with a value for one of its partition
  columns, such as `equals(t.dt, "2026-09-24")`, `between(...)`, `is_in(...)` or
  `last_n_days(t.dt, 7)`: in WHERE for FROM, JOIN and CROSS_JOIN; inside ON= for LEFT_JOIN,
  SEMI_JOIN and ANTI_JOIN; for FULL_JOIN, in a Derived table it reads. Matching it to another
  table's column bounds nothing. A table with no partitions needs no bound.
- **A6** Give every ORDER_BY a LIMIT.
- **A7** Run a read with `run_query(s, query)` and a write with `run_execute(s, execute)`,
  after `from warehouse import query, execute`. Never call query or execute yourself.
- **A8** Add an opt-out, such as `reads_all_partitions=True`, only when the user asks for
  what it allows, and say why in a comment.
- **A9** Reach a column as `table.column`, from the user's Table reference:
  `from references.ops__job_runs import job_runs`, then `job_runs.dt`.
- **A10** If this file doesn't cover the request, say so and name the file to load in a new
  chat: 01 the Project, 02 Table references, 03 a Statement, 04 joins, 05 windows and
  subtotals, 06 saving a table, 07 converting Hive, 08 checks, 09 a refusal, 10 labels and
  Hive by hand, 13 convert, 14 new tables and upkeep, 16 promote, 17 Run values and seeds, 18
  a Scheduled run, 19 a Metric request; an Excel workbook, 15 with 11 and 12.
- **A11** Read each Derived table once; SELECT in it only what is read after; filter and
  group before joining; fix rows a join repeats by its whole Key or a total first, not
  SELECT_DISTINCT.

## Worked patterns

### W1: a new Saved table's Table reference, references/mart__job_day_runs.py

```python
from sqlglot_composer import Table

job_day_runs = Table(
    "mart.job_day_runs",
    columns={"job_id": "bigint", "runs": "bigint", "minutes": "bigint", "dt": "string"},
    partitioned_by=["dt"],
    key=["job_id", "dt"],
    location="/data/your_team/mart.db/job_day_runs",
    descriptions={"runs": "the job's runs that day"},
)
```

### W2: check a table's Key on one day

```python
from sqlglot_composer import check_key, equals
from references.ops__job_runs import job_runs
from warehouse import query

v = check_key(job_runs, query=query, where=equals(job_runs.dt, "2026-09-24"))
print(v)
```
