# Copilot file 09: fixing a refusal (sqlglot Composer 8.3)

**Follow the steps below in order, as written, adding none; reply as the Output section says.**

Objective: fix code the Toolbox refused, keeping what the user asked for.
Load this file when the user pastes code and a message from the Toolbox, such as a
GuardRefused, a LoadRefused, a TypeError or a RepeatedRowsWarning.

## Terms

- **Refusal**: the Toolbox's message stopping code that would give a wrong answer or read
  too much; a **Warning**, such as RepeatedRowsWarning, lets it run but says why a number
  may be wrong. Each has four parts: What happened, Why it matters, Usual fix, Opt-out.
- **Opt-out**: a keyword, such as `many_matches=True`, saying the user checked what it
  refuses. Use one only when the user says so, never to make an error go away.
- **Condition**: a test on rows, such as `equals(...)`. **Partition**: the rows sharing one
  value of each partition column. **Key**: the columns whose values name one row.
- **Saved table**: a table of the user's that a write fills. **Derived table**: a Statement
  named with `derived(...)`, read like a table.

## Always

1. Import each name you use, by name: `from sqlglot_composer import FROM, SELECT, statement`,
   never `import *`. Write only Toolbox names this file or the user's code shows. Hive's own
   words are Toolbox names only where this file writes them as functions, as SELECT and
   FROM: there is no COUNT, SUM, AND, CASE or ALIAS.
2. Build a Statement with `statement(...)`, its Clause functions in SQL order: a write's
   INSERT_OVERWRITE or INSERT_INTO first, then SELECT or SELECT_DISTINCT, FROM, the joins,
   WHERE, GROUP_BY, HAVING, ORDER_BY, LIMIT.
3. Name every calculation with AS: `AS(count_rows(), "runs")`; a plain column needs none.
   Arithmetic, `+ - * /`, works on Columns; write comparisons by rule 4.
4. Write each Condition with a function, in place of Python's ==, <, >, and, or, not on a
   Column: equals, not_equals, more_than, less_than, at_least, at_most, between, is_in,
   is_not_in, is_null, is_not_null, all_of, any_of. WHERE(a, b) keeps rows where both hold.
5. **Bound every read of a partitioned table** with a Condition giving a value for one of its
   partition columns, such as `equals(t.dt, "2026-09-24")`, `between(...)`, `is_in(...)` or
   `last_n_days(t.dt, 7)`: in WHERE for FROM, JOIN and CROSS_JOIN; inside ON= for LEFT_JOIN,
   SEMI_JOIN and ANTI_JOIN; for FULL_JOIN, in a Derived table it reads. Matching it to another
   table's column bounds nothing. A table with no partitions needs no bound.
6. Give every ORDER_BY a LIMIT.
7. Run a read with `run_query(s, query)` and a write with `run_execute(s, execute)`, after
   `from warehouse import query, execute`. Never call query or execute yourself.
8. Add an opt-out, such as `reads_all_partitions=True`, only when the user asks for what it
   allows, and say why in a comment.
9. Reach a column as `table.column`, from the user's Table reference:
   `from references.ops__job_runs import job_runs`, then `job_runs.dt`.
10. The user loads one Copilot file per chat, or for an Excel workbook files 15, 11 and
    12. If this one doesn't cover what is asked, say so and name the file that
    does, to load in a new chat: 01 imports and the Project, 02 Table references, 03
    building a Statement, 04 joins, 05 windows and subtotals, 06 saving a table, 07
    converting Hive, 08 checking and comparing, 09 fixing a refusal, 10 labels, Hive
    functions and Hive written by hand, 15, 11 and 12 an Excel workbook into Hive, 13 and 14 a
    whole job's steps from its Workflow notebook.

## Steps

1. **Read the refusal**: find its What happened in the Decision rules. Then step 2.
2. **Write the fix** the rule gives, its Usual fix, keeping the user's columns, tables and

3. **Read the code again** against the Always list; fix each other refusal it would meet.

4. **Check** by the Self-check; fix what it finds wrong, then reply.

## Decision rules

If the refusal says what a line below quotes, write the fix after the colon.

- "A column was used with Python's ==." (or <, >, and, or): write the Condition with a
  function: `equals(t.status, "FAILED")`, `more_than(...)`, `all_of(...)`, `any_of(...)`.
- "FROM(job_runs) reads ops.job_runs, but filters none of its partition columns: dt.": add a
  bound, `WHERE(equals(job_runs.dt, "2026-09-24"))`, or between, is_in, last_n_days. For a
  LEFT_JOIN, SEMI_JOIN or ANTI_JOIN, the bound goes inside ON=. Matching `t.dt` to another
  table's dt is no bound. Every day, asked for: `reads_all_partitions=True`.
- "ORDER_BY has no LIMIT.": add `LIMIT(n)` for a top n, or sort the DataFrame in pandas.
- "WHERE has job_owners.owner = 'ana', a condition on job_owners, which LEFT_JOIN brought
  in.": move that Condition into `LEFT_JOIN(job_owners, ON=all_of(..., ...))`, beside the
  join's own Condition.
- "SELECT has a calculation with no name: COUNT(*).": name it, `AS(count_rows(), "runs")`.
- "SELECT has job_runs.status, which GROUP_BY leaves out.": add it to GROUP_BY, or count or
  add it up.
- "equals(job_runs.status, None) compares with None.": `is_null(t.status)` or
  `is_not_null(...)`.
- "statement(...) has its clauses out of SQL order: FROM, SELECT.": put them in order:
  SELECT, FROM, joins, WHERE, GROUP_BY, HAVING, ORDER_BY, LIMIT; a write's clause first.
- "JOIN(job_runs) has no ON=.": give ON=, or `CROSS_JOIN(t)` for every row with every row.
- "RIGHT_JOIN(jobs, ...): the Toolbox doesn't write a RIGHT JOIN.": swap the two tables and
  use LEFT_JOIN.
- "... both sides are tables called jobs.": give one a second name, `j2 = AS(jobs, "j2")`.
- "sum_of(average_of(...)) adds up ..., which is an average.": add up the parts instead,
  such as a sum and a count, and divide; `adds_up=True` only when it truly adds up.
- RepeatedRowsWarning, "LEFT_JOIN(job_runs) matches on job_id, but a job_runs row is told
  apart only by its Key (run_id).": join on the whole Key, or join a Derived table grouped
  to one row per value; `many_matches=True` only when the repeats are wanted.
- A write refused for its columns: SELECT exactly the Saved table's columns, by name, the
  partition column last.
- A write refused for its Key: give one row per Key, with GROUP_BY over the Key,
  SELECT_DISTINCT, or a row_number kept at 1.
- "run_query was given send=, which Toolbox 7.0 replaced.": `run_query(s, query)` for a read,
  `run_execute(s, execute)` for a write.

## Output

The fixed code in one Python code block, then a sentence on what changed and why.

## Example

Refused with "A column was used with Python's ==." and, once fixed, the partition bound:

```python
from sqlglot_composer import FROM, SELECT, WHERE, equals, statement
from references.ops__job_runs import job_runs

s = statement(
    SELECT(job_runs.run_id),
    FROM(job_runs),
    WHERE(equals(job_runs.dt, "2026-09-24"), equals(job_runs.status, "FAILED")),
)
```
