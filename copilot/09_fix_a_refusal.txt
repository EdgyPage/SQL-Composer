Objective: fix code the Toolbox refused, keeping what the user asked for.
Load this file when the user pastes code and a message from the Toolbox, such as a

## Patterns: when the message says X, fix with Y

| ID | What happened says | Fix | Rule |
|---|---|---|---|
| P1 | "used with Python's ==" (or <, >, and, or) | a Condition function | R1 |
| P2 | "filters none of its partition columns" | a bound with a value | R2 |
| P3 | "ORDER_BY has no LIMIT" | `LIMIT(n)`, or sort in pandas | R3 |
| P4 | "a condition on X, which LEFT_JOIN brought in" | the Condition moved into ON= | R4 |
| P5 | "a calculation with no name" | `AS(..., "name")` | R5 |
| P6 | "which GROUP_BY leaves out" | the column added to GROUP_BY | R6 |
| P7 | "counts or adds up rows and has no GROUP_BY" | `GROUP_BY(...)` added | R7 |
| P8 | "the logic cell ... calls run_query" | the call moved to the next cell | R8 |
| P9 | "compares with None" | `is_null(...)`, `is_not_null(...)` | R9 |
| P10 | "clauses out of SQL order" | the clauses in order | R10 |
| P11 | "has no ON=" | ON=, or `CROSS_JOIN(t)` | R11 |
| P12 | "doesn't write a RIGHT JOIN" | the tables swapped, LEFT_JOIN | R12 |
| P13 | "both sides are tables called" | a second name with AS | R13 |
| P14 | "adds up ..., which is an average" | the parts added up, then divided | R14 |
| P15 | RepeatedRowsWarning, "told apart only by its Key" | join on the whole Key | R15 |
| P16 | a write refused for its columns or Key | the table's columns; one row per Key | R16 |
| P17 | "was given send=" | `run_query(s, query)`, `run_execute(s, execute)` | R17 |

## Terms

- **Refusal**: the Toolbox's message stopping code that would give a wrong answer or read
  too much; a **Warning**, such as RepeatedRowsWarning, lets it run but says why a number
  may be wrong. Each has four parts: What happened, Why it matters, Usual fix, Opt-out.
- **Opt-out**: a keyword, such as `many_matches=True`, saying the user checked what it
  refuses. Use one only when the user says so, never to make an error go away.
- **Condition**: a test on rows, such as `equals(...)`. **Partition**: the rows sharing one
  value of each partition column. **Key**: the columns whose values name one row.
- **Derived table**: a Statement named with `derived(...)`, read like a table.

## Rules

- **R1** `equals(t.status, "FAILED")`, `more_than(...)`, `all_of(...)`, `any_of(...)`.
- **R2** Add `WHERE(equals(job_runs.dt, "2026-09-24"))`, or between, is_in, last_n_days,
  with the day the user asked for. For a LEFT_JOIN, SEMI_JOIN or ANTI_JOIN, inside ON=.
  Matching `t.dt` to another table's dt is no bound. Every day, asked for:
  `reads_all_partitions=True`.
- **R3** A top n: `LIMIT(n)` after the ORDER_BY. A whole result: no ORDER_BY, and sort the
  DataFrame, `run_query(s, query).sort_values("minutes")`.
- **R4** Move it into `LEFT_JOIN(job_owners, ON=all_of(..., ...))`, beside the join's own
  Condition.
- **R5** `AS(count_rows(), "runs")`.
- **R6** Add it to GROUP_BY, or count or add it up.
- **R7** `GROUP_BY(job_runs.job_id)`. For each group's whole latest row instead:
  `row_number(...)` in a Derived table, kept at 1 (file 05).
- **R8** The logic cell keeps imports and functions that build Statements; run_query and
  run_execute go in the next cell.
- **R9** `is_null(t.status)`, never `equals(t.status, None)`.
- **R10** SELECT, FROM, joins, WHERE, GROUP_BY, HAVING, ORDER_BY, LIMIT; a write's clause
  first.
- **R11** `JOIN(t, ON=equals(...))`, or `CROSS_JOIN(t)` for every row with every row.
- **R12** There is no RIGHT_JOIN: swap the two tables and use LEFT_JOIN.
- **R13** `j2 = AS(jobs, "j2")`, then `j2.job_id`.
- **R14** Add up a sum and a count and divide; `adds_up=True` only when it truly adds up.
- **R15** Join on the joined table's whole Key, or a Derived table grouped to one row per
  value; `many_matches=True` only when the repeats are wanted.
- **R16** SELECT exactly the Saved table's columns, by name, the partition column last; one
  row per Key by GROUP_BY over the Key, SELECT_DISTINCT, or a row_number kept at 1.
- **R17** `send=` went in 7.0: `run_query(s, query)` reads, `run_execute(s, execute)`
  writes.

## Always: rules A1 to A11

- **A1** Import each name you use, by name: `from sqlglot_composer import FROM, SELECT,
  statement`, never `import *`. Write only Toolbox names this file or the user's code shows:
  there is no COUNT, SUM, AND, CASE or ALIAS function.
- **A2** One `statement(...)`, its Clause functions in SQL order: a write's INSERT_OVERWRITE
  or INSERT_INTO first, then SELECT or SELECT_DISTINCT, FROM, the joins, WHERE, GROUP_BY,
  HAVING, ORDER_BY, LIMIT.
- **A3** Name every calculation with AS: `AS(count_rows(), "runs")`; a plain column needs
  none. `+ - * /` work on Columns; comparisons are A4's.
- **A4** Write each Condition with a function, never Python's ==, <, >, and, or, not on a
  Column: equals, not_equals, more_than, less_than, at_least, at_most, between, is_in,
  is_not_in, is_null, is_not_null, all_of, any_of. WHERE(a, b) keeps rows where both hold.
- **A5** **Bound every read of a partitioned table** with a value for one of its partition
  columns, such as `equals(t.dt, "2026-09-24")`, `between(...)`, `is_in(...)` or
  `last_n_days(t.dt, 7)`: in WHERE for FROM, JOIN and CROSS_JOIN; inside ON= for LEFT_JOIN,
  SEMI_JOIN and ANTI_JOIN; for FULL_JOIN, in a Derived table it reads. Matching it to another
  table's column bounds nothing. A table with no partitions needs no bound.
- **A6** Give every ORDER_BY a LIMIT.
- **A7** Run a read with `run_query(s, query)` and a write with `run_execute(s, execute)`,
  after `from warehouse import query, execute`. Never call query or execute yourself.
- **A8** Add an opt-out, such as `reads_all_partitions=True`, only when the user asks for
  what it allows, and say why in a comment.
- **A9** Reach a column as `table.column`, from the user's Table reference:
  `from references.ops__job_runs import job_runs`, then `job_runs.dt`.
- **A10** If this file doesn't cover the request, say so and name the file to load in a new
  chat: 01 the Project, 02 Table references, 03 a Statement, 04 joins, 05 windows and
  subtotals, 06 saving a table, 07 converting Hive, 08 checks, 09 a refusal, 10 labels and
  Hive by hand, 13 convert, 14 new tables and upkeep, 16 promote, 17 Run values and seeds, 18
  a Scheduled run, 19 a Metric request; an Excel workbook, 15 with 11 and 12.
- **A11** Read each Derived table once; SELECT in it only what is read after; filter and
  group before joining; fix rows a join repeats by its whole Key or a total first, not
  SELECT_DISTINCT.

## Worked patterns

### W1: refused with "A column was used with Python's ==.", then bounded on its day

```python
from sqlglot_composer import FROM, SELECT, WHERE, equals, statement
from references.ops__job_runs import job_runs

s = statement(
    SELECT(job_runs.run_id),
    FROM(job_runs),
    WHERE(equals(job_runs.dt, "2026-09-24"), equals(job_runs.status, "FAILED")),
)
```
