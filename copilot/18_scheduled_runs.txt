## Terms

- **Scheduled run**: a notebook in scheduled_runs/<name>/, run top to bottom: the Build cell
  prints the Hive and sends nothing; the Run cell sends it.
- **Parameter**: a value the scheduler passes in, a name in the `# parameters` cell, read by
  its type hint before anything is built.
- **Logic function**: a function of a Table notebook's `# logic` cell giving a Statement;
  `project.load("mart.team_days")` gives them; describe_logic prints each one's signature
  and docstring's first sentence, under its table's name.
- **Run value**: what a function gives each time the run is built, through
  `run_value(function)`, such as the latest Partition a table holds.

## Rules

- **R1** Each parameter is a name, a hint and a default: `RUN_DATE: datetime.date | None =
  None`. The hints: `datetime.date` (from "2026-11-01"), `int`, `float`, `bool` ("true" or
  "false"), `str`, each alone, in `list[...]` (split at commas) or with `| None`. Never one
  without a hint, nor another hint. Keep `START_FROM: str = ""`.
- **R2** `| None = None` only if the cell works a value out when it is None; else a real
  default, `WEEK: datetime.date = datetime.date(2026, 9, 23)`: the notebook also runs as it
  is, in Jupyter.
- **R3** A logic function's arguments are given in the call, `team_days.week_totals(first,
  last)`; a date parameter where the signature says `str` is `str(RUN_DATE)`.
- **R4** A day worked out at each run is a function of the cell, taking nothing and reading
  the parameters, passed as `run_value(week_first_day)`. A logic function working on a day's
  text, as a `write_days` may, refuses a Run value: give it `str(...)`, worked out in
  `statements()`.
- **R5** `statements()` returns a dict of each Statement by name: a SELECT by what its rows
  are, read back as `results["week_totals"]`; a write by its table's short name. The build
  adds the write of each Project table they read, all the way up, on its own days: never
  list those. Another run or job writes a table: `leave_out=["mart.job_day_facts"]`.
- **R6** A table written for the run's period, not its own days: the logic function the paste
  lists for it that takes days, such as `team_days.write_days(first, last)`, in
  `statements()` by its short name, in place of the write the build adds.
- **R7** A Script tag answered `hivevar("PERIOD_END", ...)`, its value given for this run:
  `hivevars={"PERIOD_END": RUN_DATE}` in the Build cell; left out, its default is sent.
- **R8** A parameter reaches only what `statements()` passes it to; a write the build adds is
  its table's `write()`, which takes nothing. Its Run value given the user's value:
  `run_values={"period_end": RUN_DATE}`, by the function's name; else `{}`.
- **R9** A failed run printed `START_FROM = "mart.team_days"`: the scheduler passes it, and
  the build starts there; never write it into the cell.
- **R10** The setup cell stays as the Template writes it, but its `connect(...)` line: the
  user's connection, its `#` deleted. A Statement of the user's own is composed in the cell
  (file 03); a Guard it trips only warns there: add no opt-out.

The paste:

def week_totals(first_day: str, last_day: str) -> Statement:

### W1: each team's week, of WEEK or of the latest day ops.job_events holds

```python
# parameters
import datetime

START_FROM: str = ""  # a table or SELECT to start from, as a failed run prints it
WEEK: datetime.date | None = None  # a day of the week, such as "2026-09-23"; None: the latest
```

```python
# scheduled
from sqlglot_composer import Statement, latest_partition, project, run_value
from references.ops__job_events import job_events
from warehouse import query


def week_first_day() -> datetime.date:
    """The Monday of WEEK's week, or of the latest day ops.job_events holds."""
    day = WEEK if WEEK is not None else latest_partition(job_events.dt, query)
    return day - datetime.timedelta(days=day.weekday())


def week_last_day() -> datetime.date:
    """The Sunday after week_first_day."""
    return week_first_day() + datetime.timedelta(days=6)


def statements() -> dict[str, Statement]:
    """What this run sends, by name: the build adds the writes of each table they read."""
    team_days = project.load("mart.team_days")
    return {"week_totals": team_days.week_totals(run_value(week_first_day),
                                                 run_value(week_last_day))}

# Build
built = project.build_run(statements, run_values={}, leave_out=[])
```

The setup cell's line: `connect(my_api.connect())`.

### W2: a Statement of its own, the failed runs of RUN_DATE

```python
import datetime

from sqlglot_composer import FROM, SELECT, WHERE, Statement, equals, statement
from references.ops__job_runs import job_runs

RUN_DATE: datetime.date = datetime.date(2026, 9, 24)


def statements() -> dict[str, Statement]:
    """The day's failed runs."""
    return {"failed_runs": statement(
        SELECT(job_runs.run_id, job_runs.job_id), FROM(job_runs),
        WHERE(equals(job_runs.dt, str(RUN_DATE)), equals(job_runs.status, "FAILED")))}
```
