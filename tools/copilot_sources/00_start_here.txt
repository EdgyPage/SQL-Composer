# Copilot files for {version}: start here

**Find the words you would type in the Index, load the file it names into a new chat, then
follow the steps below in order.**

{version} writes Hive, the SQL of your warehouse, from Python: you build a Statement from
Clause functions, such as SELECT, FROM and WHERE, and the Toolbox writes its Hive and refuses
one that would give a wrong number or read too much. These files teach Microsoft Copilot to
write that Python, so you can ask it in plain words.

## Rules: when two lines seem to fit

- **R1** The Toolbox refused your code: 09, whatever the code does.
- **R2** Someone else's Hive: as Toolbox code to read, 07; made into Saved tables in your
  Project, end to end, 13; carried from dev to prod once compared, 16.
- **R3** A Script tag's day worked out at each run, such as the latest Partition a table
  holds, one answer for every table, or a seed of only some Partitions: 17, even in the
  middle of a convert. A tag's value given once, for this run: in a convert, 13; as Toolbox
  code to read, 07 (R2).
- **R4** A Script tag left as a Hivevar, `${hivevar:NAME}` for your scheduler: 17; a
  Scheduled run's own value of it: 18.
- **R5** Your chatbot's Hive (file 19's end): as Toolbox code, 07; as a Saved table, saved
  as a .hql file, 14.
- **R6** For an Excel workbook, attach files 15, 11 and 12 (or paste each as a message of
  its own), then the workbook: a chat holds one file at a time, but for this one task.
- **R7** Two tasks: a new chat for each, with each task's file.
- **R8** One file each: a request that ends "and run it with my query", or reads "using my
  Database module", is 01, whatever it reads; checking a Key holds on the warehouse, even
  "with my query", is 08; writing a Key into a reference is 02.

## Terms

- **Copilot file**: one of the files in this folder; each teaches Copilot one objective.
- **Statement**: one query, built in Python with `statement(...)`, that becomes Hive.
- **Project**: your folder at work holding the Toolbox and your own code.
- **Table reference**: the file in your Project's references/ folder that describes one
  table: its columns and their types, its partitions and its Key.
- **Saved table**: a table in the warehouse that your own Statements write.
- **Workflow**: the steps to one end goal, such as converting Hive, each a cell of the
  Workflow's notebook in admin/workflows/.
- **Run value**: the value a function of yours works out each time a table is written.
- **Your chatbot**: the chatbot at your work that knows your databases; not Copilot.

## Steps

1. **Choose.** Find your words in the Index, and the Rules where two lines fit. Done when
   you have one file, or three for a workbook. Then step 2.
2. **Load.** Open a new chat in Copilot; paste the file as your first message and send it,
   or attach it if a paste is cut short. Then step 3.
3. **Ask.** Name each table to read: paste its Table reference, or say its import line and
   columns, such as: `from references.ops__job_runs import job_runs` gives ops.job_runs:
   run_id bigint, job_id bigint, status string, dt string; partitioned by dt; Key run_id.
   For file 19, paste your column definitions and say the metric; for a workbook, attach
   it. Then step 4.
4. **Run.** Run what Copilot gives in your notebook. If the Toolbox refuses it, start a new
   chat with file 09, paste the code and the whole message, and ask for the fix. A
   workbook's Hive: save each query as a .hql file and run the convert Workflow (file 13).
   File 19: answer each question, then paste the Metric request into your chatbot.

## Which file

- `01_imports_and_project.txt`: start a Project, import the Toolbox, your Table
  references and warehouse.py's query and execute, and run a Statement.
- `02_table_references.txt`: describe a table: add its Table reference, or write one by
  hand for a Saved table, with its columns, partitions and Key (checking it holds: 08).
- `03_build_a_statement.txt`: read rows: pick columns, filter, count, add up, group, sort,
  and build in steps with Derived tables.
- `04_joins.txt`: combine tables with JOIN, LEFT_JOIN and the others.
- `05_windows_and_subtotals.txt`: a rank or row number in each group, the latest row or top N
  of each group, the row before, running totals; subtotals; stacking Statements.
- `06_save_a_table.txt`: write a Saved table: its Table notebook's logic cell, with
  create(), rows(), preview() and write().
- `07_convert_hive.txt`: turn one query of Hive someone else wrote into Toolbox code; for
  their Hive made into tables, a whole job, file 13.
- `08_check_and_compare.txt`: compare a Statement with the Hive it replaces, check a Key, see
  what is left to do in the Project, follow lineage.
- `09_fix_a_refusal.txt`: fix code the Toolbox refused.
- `10_hand_written_hive_and_functions.txt`: labels from a lookup or a chain of if/else,
  Hive functions the Toolbox doesn't wrap, Hive written by hand, and upkeep of a table.
- `11_excel_formula_workbooks.txt`: each formula of a Formula workbook, an Excel workbook
  laid out as `formula_workbook.xlsx` shows, as Hive; loaded with files 15 and 12.
- `12_excel_power_query.txt`: the same workbook's Power Query, whole-column totals and Total
  Rows as Hive; loaded with files 15 and 11.
- `13_workflows.txt`: converting Hive into Saved tables in dev, a whole job step by step,
  from the convert Workflow's notebook in admin/workflows/.
- `14_workflows_new_tables_and_upkeep.txt`: a new Saved table, from a query or by hand,
  Table references, an upgrade, a change to a Saved table, each a whole job step by step.
- `15_excel_workbook_steps.txt`: turn a Formula workbook into Hive, step by step: which
  Tables and queries become which queries, and the reply; loaded with files 11 and 12.
- `16_workflows_promote.txt`: promoting dev tables to prod, a whole job step by step, from
  the promote Workflow's notebook.
- `17_run_values_and_seed_limits.txt`: a Run value, the value a function of yours works out
  each time a table is written, such as a Script tag's day, or a Hivevar; answers for every
  table of a Workflow notebook; and seed limits, the Partitions a seed copies.
- `18_scheduled_runs.txt`: a Scheduled run, a notebook an outside scheduler such as
  papermill runs top to bottom: its parameters, the Statements it runs, from a
  `project.describe_logic([...])` paste, and its Build cell.
- `19_metric_request.txt`: a new metric, defined a question at a time from your column
  definitions: one column or two, each quantity, the rows, the days, what is left out, and
  any data missing; it ends with a Metric request, text for your chatbot, not code or sums.

## Fitting Copilot

- Each file is at most 9,000 characters, so it goes to Copilot in one message. Count an
  edited copy from the download's top folder: `python copilot/count_characters.py my_copy.txt`.

## Self-check

- [ ] **C1** The chat is new, and its first message is the file the Index names (for a
  workbook, files 15, 11 and 12).
- [ ] **C2** Your question names each table to read; for file 19, your column definitions
  and the metric.
- [ ] **C3** For a refusal, the new chat holds file 09, your code and the whole message.
