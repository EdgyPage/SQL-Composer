# Copilot file 02: Table references ({version})

**Follow these steps in order, as written: add no step, skip none, and reply as Output says.**

Objective: describe a table to the Toolbox with a Table reference, and check what it says.
Load this file when the user adds a table to read, writes the Table reference of a new Saved
table, or asks about a table's columns, partitions or Key.

## Terms

- **Toolbox**: {version}, which writes Hive from Python.
- **Table reference**: the file references/<database>__<table>.py, such as
  references/ops__job_runs.py, defining one table's Table.
- **Key**: the columns that tell one row from another.
- **Saved table**: a table the user's own notebook writes.
- **Workflow**: a job's steps, run from its notebook in admin/workflows/; a **Decision**,
  what only the user answers, in its decisions cell.
- **Condition**: a test on rows, such as `equals(...)`; a **Statement**, one Hive query.

{always}

## Names for this objective, with their arguments

{names: project.add_references, write_table_reference, Table, check_key, check_table_reference, first_look, all_columns, equals, between, is_in}

## Where one comes from

- A table that exists: the references Workflow, admin/workflows/references/references.ipynb,
  runs `project.add_references(["ops.job_runs"], query=query)`, writing its Table reference
  from the warehouse's own description, so its columns and types are right. Its Key is a
  Decision, `DECISIONS = {"ops.job_runs": {"key": ["run_id"]}}`, which the next step writes.
- A new Saved table: the new_table Workflow (file 14) writes its Table reference from its
  logic, `project.reference_from_logic(TABLES)`, or from its query; the user answers its
  location in the decisions cell.

## Table's arguments

- `columns={"run_id": "bigint", "status": "string", "dt": "string"}`: every column, in
  order, each with its Hive type: string, int, bigint, double, boolean, date, timestamp,
  decimal(10,2), array<string>, map<string,int>, struct<name:string>.
- `partitioned_by=["dt"]`: the partition columns, listed in `columns` too, last.
- `key=["job_id", "dt"]`: the Key, which makes the Toolbox trust a join or a write.
- `does_not_add_up=["share"]`: columns the Toolbox refuses to add up, such as a share or an
  average.
- `location="/data/your_team/mart.db/job_day_runs"`: where a Saved table's files go.
- `descriptions={"status": "FAILED, SUCCESS or NULL while running"}`: what a column
  means, for Lineage and the Reference sheet, the Project's pages of its columns.
- A Condition used often may sit beside its Table, such as
  `finished = is_in(job_runs.status, ["SUCCESS", "FAILED"])`.

## Checks

- `check_key(t, query=query, where=...)` counts whether the Key really tells each row apart,
  on the partitions `where=` names.
- `check_table_reference(t, query=query)` lists what differs from the table as the
  warehouse has it now.
- `first_look(t)` is a Statement of all its columns and 20 rows, for `run_query`.
- A check gives back a Verdict `v`: `print(v)` says whether the Key holds; `if v:` is true
  when it does.

## Steps

1. **Read.** Goal: know the table. Action: list its name, columns, partitions and any Key
   the user gives. Done when each column has a Hive type; then step 2.
2. **Write.** Action: write the code by this file. Done when every name is imported; then
   step 3.
3. **Check.** Action: run the Self-check; fix what fails, then reply.

## Decision rules

- If the user names a Key, write it as `key=`. If not, leave `key=` out, or ask.
- If it is a Saved table, give it a `location=`. If it is only read, give none.
- If asked to write a database's file, such as references/ops.py: the Project actions do.

## Output

Reply with these parts, in this order, and nothing else:

1. **Code**: one ```python block the user can paste into a notebook cell or a file.
2. **Notes**: a few plain sentences on what it gives.

## Examples

A new Saved table's Table reference, references/mart__job_day_runs.py:

```python
from sqlglot_composer import Table

job_day_runs = Table(
    "mart.job_day_runs",
    columns={"job_id": "bigint", "runs": "bigint", "minutes": "bigint", "dt": "string"},
    partitioned_by=["dt"],
    key=["job_id", "dt"],
    location="/data/your_team/mart.db/job_day_runs",
    descriptions={"runs": "the job's runs that day"},
)
```

Check a table's Key on one day:

```python
from sqlglot_composer import check_key, equals
from references.ops__job_runs import job_runs
from warehouse import query

v = check_key(job_runs, query=query, where=equals(job_runs.dt, "2026-09-24"))
print(v)
```

## Self-check

- The Table's name is "database.table", and the file and the variable are named after it.
- Each column has a Hive type, never a Python one such as `int` or `str`.
- Partition columns are in `columns` and in `partitioned_by`.
- Checks pass `query=query` and bound a partitioned table with `where=`.
