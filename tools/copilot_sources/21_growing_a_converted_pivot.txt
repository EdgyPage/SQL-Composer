## Terms

- **Converted pivot**: a Saved table convert made from a PivotTable. Its Table notebook's
  logic cell has rows(), the clauses convert wrote, which create(), preview() and write()
  read. Saved table, Table reference, Partition: as file 06 says.
- **Pivot filter**: what the PivotTable left out (a Report filter, hidden items, a slicer, a
  Timeline, a value filter), each a **Decision** of its table, answered in the convert
  notebook's decisions cell, DECISIONS. A **layer**: each field a table is filtered on.
- `d`: a Derived table; `t`: a table.

## Rules: add-ons

- **R1** Change rows(), and the Derived tables above it, in the logic cell; create(),
  preview() and write() stay. **Never a change to the workbook**, nor a convert again: the
  workbook is a one-time way in.
- **R2** Each column added goes in the Table reference's columns, in SELECT's order, the
  partition column last; a share or rank in does_not_add_up. Created in dev already: file
  14's change to a Saved table first.
- **R3** **A Window over the pivot's sums reads them from a Derived table** grouped as rows()
  was; never a sum_of inside a sum_of. % of the grand total: `AS(d.x / sum_of(d.x,
  over=window()), "share")`; of a row or column total, `window(PARTITION_BY=d.dt)`.
- **R4** Running Total In b: `sum_of(d.x, over=window(PARTITION_BY=d.job_id, ORDER_BY=d.b,
  rows=(None, 0)))`.
- **R5** Rank Largest to Smallest: `rank(over=window(PARTITION_BY=d.dt,
  ORDER_BY=descending(d.x)))`; Smallest to Largest, `ORDER_BY=d.x`.
- **R6** A Calculated Field: its formula over the sums, one AS: `AS(sum_of(t.duration_mins)
  / 60, "hours")`; a ratio, one sum over the other.
- **R7** By month: `AS(month_start(t.dt), "month")` in SELECT, `"month"` in GROUP_BY; by
  week, `week_start(t.dt)`. Two years' Septembers stay apart.
- **R8** Wide, a column per value: `AS(sum_of(t.x, where=equals(t.status, "FAILED")),
  "failed_x")`, the field out of GROUP_BY. A new value has no column: convert wrote rows.
- **R9** Every total level in one Statement (file 05's R5), in place of reading the
  `<pivot>_by_...` and `<pivot>_grand_total` tables:
  - if Rows and Columns, both Grand Totals shown: `GROUP_BY(cube(t.job_id, t.dt))`;
  - if Rows alone, with subtotals: `GROUP_BY(rollup(t.team, t.job_id))`.
- **S1** A converted pivot reads every day, `reads_all_partitions=True`. To scale: dt in
  SELECT, last, and GROUP_BY, the table partitioned by it, rows(day) bounded by
  `equals(t.dt, day)`: each run writes one day (file 06's R6).

## Rules: Pivot filters at scale

- **F1** Answer each filter by its field in DECISIONS, as W3, then run
  `project.write_decisions(DECISIONS, tables=project.batch_tables(NAME))`.
- **F2** "keep", proposed: 1 table, the selection as last saved. Pick it when that one
  selection is all anyone needs.
- **F3** "fold", like dragging the field from Filters to Rows: 1 table, every value, the
  field part of what one row is. Pick it to slice later, as with a slicer.
- **F4** "batch": 1 table, a Partition per value, each run writing one value, a Script tag
  answered under "tags" (file 17), its answer proposed. Pick it for a value a run.
- **F5** "tables", like Show Report Filter Pages: a table per value, `<table>_<value>`, at
  least one per value the PivotTable's cache held; two layers multiply: Region 3 and Site
  100 make at least 300. **A filter with 100 conditions would make 100 tables, but the
  higher layer filter may have only 3, which is manageable.** Pick it for a handful; for a
  hundred, "fold" or "batch". Say each count first.
- **F6** A value filter (Top 10): "keep" or "fold"; a .hql converted alone has no count,
  so not "tables".

## Rules: what no Decision does

- **B1** **Pivots the same but for their filter's values are one table**, partitioned on
  the field (`PARTITIONED_BY`); rows() keeps each pivot's values with `is_in`, the field
  last in SELECT and in GROUP_BY. One write fills each Partition, a pivot's rows each; a
  reader of one reads its Partition, `equals(t.region, "us")`.
- **B2** A Partition a write: rows(region) bounded by `equals(t.region, region)`, write()
  `statement(INSERT_OVERWRITE(t, partition={"region": REGION}), *rows(REGION))`, the field
  out of SELECT, REGION a constant or a Run value (file 17).

## Worked patterns

### W1: rows() with each job's share of its day

```python
# logic
from sqlglot_composer import AS, FROM, GROUP_BY, SELECT, Clause, derived, statement, sum_of, window
from references.ops__job_runs import job_runs

by_day = derived("by_day", statement(
    SELECT(job_runs.job_id, job_runs.dt, AS(sum_of(job_runs.duration_mins), "mins")),
    FROM(job_runs, reads_all_partitions=True),  # as convert wrote it
    GROUP_BY(job_runs.job_id, job_runs.dt),
))


def rows() -> list[Clause]:
    return [
        SELECT(by_day.job_id, by_day.dt, by_day.mins,
               AS(by_day.mins / sum_of(by_day.mins, over=window(PARTITION_BY=by_day.dt)),
                  "share_of_day")),
        FROM(by_day),
    ]
```

### W2: two pivots, eu and us costs, one table partitioned by region

```python
# logic
from sqlglot_composer import AS, FROM, GROUP_BY, SELECT, WHERE, Clause, is_in, sum_of
from references.ops__region_costs import region_costs

PARTITIONED_BY = ["region"]


def rows() -> list[Clause]:
    return [
        SELECT(region_costs.job_id, AS(sum_of(region_costs.cost_cents), "cents"),
               region_costs.region),
        FROM(region_costs),
        WHERE(is_in(region_costs.region, ["eu", "us"])),
        GROUP_BY(region_costs.job_id, region_costs.region),
    ]
```
