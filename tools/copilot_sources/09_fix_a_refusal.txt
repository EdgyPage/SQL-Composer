## Terms

- **Refusal**: the Toolbox's message stopping code that would give a wrong answer or read
  too much; a **Warning**, such as RepeatedRowsWarning, lets it run but says why a number
  may be wrong. Each has four parts: What happened, Why it matters, Usual fix, Opt-out.
- **Opt-out**: a keyword, such as `many_matches=True`, saying the user checked what it
  refuses. Use one only when the user says so, never to make an error go away.
- **Condition**: a test on rows, such as `equals(...)`. **Partition**: the rows sharing one
  value of each partition column. **Key**: the columns whose values name one row.
- **Derived table**: a Statement named with `derived(...)`, read like a table.

## Rules

- **R1** `equals(t.status, "FAILED")`, `more_than(...)`, `all_of(...)`, `any_of(...)`.
- **R2** Add `WHERE(equals(job_runs.dt, "2026-09-24"))`, or between, is_in, last_n_days,
  with the day the user asked for. For a LEFT_JOIN, SEMI_JOIN or ANTI_JOIN, inside ON=.
  Matching `t.dt` to another table's dt is no bound. Every day, asked for:
  `reads_all_partitions=True`.
- **R3** A top n: `LIMIT(n)` after the ORDER_BY. A whole result: no ORDER_BY, and sort the
  DataFrame, `run_query(s, query).sort_values("minutes")`.
- **R4** Move it into `LEFT_JOIN(job_owners, ON=all_of(..., ...))`, beside the join's own
  Condition.
- **R5** `AS(count_rows(), "runs")`.
- **R6** Add it to GROUP_BY, or count or add it up.
- **R7** `GROUP_BY(job_runs.job_id)`. For each group's whole latest row instead:
  `row_number(...)` in a Derived table, kept at 1 (file 05).
- **R8** The logic cell keeps imports and functions that build Statements; run_query and
  run_execute go in the next cell.
- **R9** `is_null(t.status)`, never `equals(t.status, None)`.
- **R10** SELECT, FROM, joins, WHERE, GROUP_BY, HAVING, ORDER_BY, LIMIT; a write's clause
  first.
- **R11** `JOIN(t, ON=equals(...))`, or `CROSS_JOIN(t)` for every row with every row.
- **R12** There is no RIGHT_JOIN: swap the two tables and use LEFT_JOIN.
- **R13** `j2 = AS(jobs, "j2")`, then `j2.job_id`.
- **R14** Add up a sum and a count and divide; `adds_up=True` only when it truly adds up.
- **R15** Join on the joined table's whole Key, or a Derived table grouped to one row per
  value; `many_matches=True` only when the repeats are wanted.
- **R16** SELECT exactly the Saved table's columns, by name, the partition column last; one
  row per Key by GROUP_BY over the Key, SELECT_DISTINCT, or a row_number kept at 1.
- **R17** `send=` went in 7.0: `run_query(s, query)` reads, `run_execute(s, execute)`
  writes.

## Worked patterns

### W1: refused with "A column was used with Python's ==.", then bounded on its day

```python
from sqlglot_composer import FROM, SELECT, WHERE, equals, statement
from references.ops__job_runs import job_runs

s = statement(
    SELECT(job_runs.run_id),
    FROM(job_runs),
    WHERE(equals(job_runs.dt, "2026-09-24"), equals(job_runs.status, "FAILED")),
)
```
