Objective: check that a Statement gives what it should, and that the Project is in order.
Load this file when the user asks whether their Statement matches the Hive it replaces,
whether a table's Key holds, what is left to do in the Project, or where a column comes from.

## Terms

- **Statement**: one Hive query, built with `statement(...)`.
- **Verdict**: what each check gives back: `print(v)` says what it found, and `if v:` reads
  true when it holds.
- **Partition**: the rows sharing one value of each partition column. **Key**: the columns
  whose values tell each row apart.
- **Table reference**: the user's file describing one table: its columns, Partitions and Key.
- **Lineage**: which table columns feed each output column.

## Rules

- **R1** `compare_hive(s, original)` compares the Statement's Hive with `original`, the Hive
  as a string, by its text, and sends nothing. Spacing, case, comments and short table names
  don't count; a different condition does, even one giving the same rows.
- **R2** `compare_with_original(s, original, query=query, partition={"dt": day})` reads both
  through the user's query on one Partition and counts the rows in one and not the other.
  The original's columns must be the Statement's, same names, same order. No day given: ask.
- **R3** Every Partition, asked for: `reads_all_partitions=True` in place of `partition=`.
- **R4** `check_key(t, query=query, where=...)` says whether the Key tells each row apart
  on the Partitions `where=` names, one day or a range.
- **R5** `check_table_reference(t, query=query)` lists what differs from the table now.
- **R6** `project.check()` lists what is left: a Decision to answer, a Workflow's next step;
  it notes each `# CONVERSION:` mark, which blocks nothing.
- **R7** A converted batch again, on another Partition, once finished too:
  `project.compare_batch("ops_reports", query=query, partitions=[{"dt": "2026-09-23"}])`.
- **R8** `export_lineage(write())` writes the Lineage page beside the notebook, as HTML, a
  box's Hive shown in a side panel when clicked, and as Markdown.
  `project.export_project_lineage()` draws every Saved table, in admin/lineage/.
- **R9** `run_query(explain(s), query)` gives Hive's plan without running;
  `print(to_hive(s))` or `show_hive(s)` shows the Hive.
- **R10** A Table notebook's Hive: save it, then run its `export_hive()` cell, after the
  lineage cell; it writes <db>__<table>.hql beside it, to read, never to edit. One
  Statement's: `export_hive(weekly)` writes weekly.hql, one call per variable.

## Worked patterns

### W1: the team's Hive compared with the Statement, by rows on one day, then by text

```python
from sqlglot_composer import (FROM, SELECT, WHERE, compare_hive, compare_with_original,
                              equals, statement)
from references.ops__job_runs import job_runs
from warehouse import query

HIVE = "SELECT run_id, status FROM ops.job_runs WHERE dt = '2026-09-23'"

s = statement(
    SELECT(job_runs.run_id, job_runs.status),
    FROM(job_runs),
    WHERE(equals(job_runs.dt, "2026-09-23")),
)
v = compare_with_original(s, HIVE, query=query, partition={"dt": "2026-09-23"})
print(v)
print(compare_hive(s, HIVE))
```

### W2: a Key of a table partitioned by two columns, on one day

```python
from sqlglot_composer import check_key, equals
from references.ops__region_costs import region_costs
from warehouse import query

v = check_key(region_costs, query=query, where=equals(region_costs.dt, "20260921"))
print(v)
```
